# Инструкция по эксплуатации и устранению неполадок (RUNBOOK.md)

В этом документе описаны типовые нештатные ситуации, регламент мониторинга и порядок действий администратора.

---

## 1. Как проверять здоровье системы

1. **Дашборд:** откройте вкладку **«Здоровье системы»** на дашборде.
   - Проверьте «Возраст последних данных». Норма: **≤ 15–20 минут**.
   - Если возраст > 30 минут — проверьте вкладку `Actions` в GitHub репозитории.
2. **Метрики в БД:**
   ```sql
   select started_at, workflow, requests, ok, http_401, http_403, http_429_1015, stale_slices
   from collector_runs
   order by started_at desc
   limit 10;
   ```

## 2. Диагностика ошибок и кодов API

### 2.1. Ошибка 401 Unauthorized
- **Причина:** Токен приложения (`Client-Id` / `Client-Secret`) отсутствует, аннулирован разработчиками EXBO, либо у приложения отозван доступ.
- **Действие:**
  1. Проверьте секреты `STALCRAFT_CLIENT_ID` и `STALCRAFT_CLIENT_SECRET` в GitHub Secrets.
  2. Зайдите в Telegram-бота `@stalzone_api_bot` командой `/myapps` и убедитесь, что приложение активно.

### 2.2. Ошибка 403 Forbidden
- **Причина:** Cloudflare отклонил запрос по отпечатку User-Agent или репутации IP-адреса.
- **Действие:**
  1. Убедитесь, что в `config.yaml` / переменных окружения задан уникальный `User-Agent`.
  2. Если блокируются все раннеры GitHub Actions — переключите сборщик на локальный ПК (запуск по Windows Task Scheduler / systemd) — домашние IP обладают высокой репутацией у Cloudflare.

### 2.3. Ошибка 429 с кодом «1015» в теле
- **Причина:** Превышен лимит частоты запросов Cloudflare на конкретный IPv4-адрес раннера (~22 rps).
- **Действие:**
  - Не наказывать токен приложения! Токен исправен.
  - Текущий запуск сборщика завершается немедленно. Следующий запуск раннера GitHub автоматически получит новый IP-адрес.
  - Убедитесь, что `rate_limit_rps` в `config.yaml` не превышает 4–5 rps.

### 2.4. Ошибка 429 без «1015» (с заголовком `Retry-After`)
- **Причина:** Исчерпана минутная квота приложения EXBO.
- **Действие:**
  - Клиент автоматически ожидает `Retry-After` секунд.
  - Если ошибка повторяется, увеличьте интервалы опроса в `config.yaml`.

### 2.5. Устаревший срез (Stale Slice)
- **Признак:** Ответ `200 OK`, но лоты не отсортированы по запрошенному `sort/order`.
- **Действие:**
  - Клиент детектирует нарушение порядка автоматически, отбрасывает срез и увеличивает счётчик `stale_slices`.
  - Никаких ручных действий не требуется; следующий запуск с другого IP вернёт корректный срез.

## 3. Заполнение базы данных (> 350 МБ)

Supabase Free предоставляет 500 МБ. Бюджет сервиса — ≤ 400 МБ.

1. **Если размер превысил 350 МБ:**
   - Автоматически срабатывает аварийное усечение ретеншна (неактивные лоты с 14 до 7 дней, продажи не-hot предметов до 14 дней).
   - Запустите ручную очистку через SQL Console в Supabase:
     ```sql
     select * from prune_old_data(7, 14);
     vacuum (analyze) lots;
     vacuum (analyze) sales;
     ```
2. **Если размер превысил 450 МБ:**
   - Запись сырых лотов блокируется до освобождения места, чтобы избежать превышения лимита тарифа.

## 4. Отключение расписания GitHub Actions (60 дней неактивности)

- На публичных репозиториях GitHub автоматически отключает `cron` через 60 дней отсутствия коммитов.
- В проекте настроен workflow `.github/workflows/keepalive.yml`, который делает служебный коммит 1-го числа каждого месяца.
- **Если расписание всё же отключилось:**
  1. Зайдите во вкладку `Actions` в вашем репозитории.
  2. GitHub покажет предупреждение: *"Workflows are scheduled to run, but have been paused"*.
  3. Нажмите кнопку **"Enable workflows"**.

## 5. Смена доменов или API-эндпоинтов

EXBO может переключать адреса между `stalcraft.net` и `stalzone.com`.
В `config.yaml` настроены основной и резервный адрес:
```yaml
market:
  base_url: "https://eapi.stalcraft.net"
  backup_base_url: "https://eapi.stalzone.com"
  demo_url: "https://dapi.stalcraft.net"
```
Клиент автоматически пробует резервный адрес при сетевых сбоях на основном.
