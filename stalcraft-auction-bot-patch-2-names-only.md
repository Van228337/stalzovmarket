# Корректировка №2: комиссия подтверждена, добавление только по человеческому названию

> **Приоритет (от высшего к низшему):** этот файл → `stalcraft-auction-bot-patch-watchlist.md` (корректировка №1) → `stalcraft-auction-bot-agent-prompt.md` (основной промпт). Всё, что здесь не упомянуто, остаётся как в предыдущих файлах.

---

## 1. Комиссия — подтверждено пользователем

- **Залога, сбора при выставлении и прочих удержаний нет.**
- **Комиссия 5% удерживается с цены продажи.**

В `config.yaml` теперь без пометок «требует подтверждения»:

```yaml
auction_fee_rate: 0.05
listing_fee: 0
fee_applies_to: sale_price
```

Что убрать из корректировки №1:

- Уточняющий вопрос пользователю про залог и базу начисления — **не задавать**.
- Оговорку в `caveats` сигналов «комиссия принята как 5%… не подтверждено» — **не выводить**.
- Пункт «Что сообщить пользователю по завершении Фазы 1», третий подпункт (подтверждение комиссии) — удалить.

Формула остаётся: `net_sell(x) = x * 0.95`, безубыточность `sell ≥ buy / 0.95 ≈ buy × 1.0526`.

## 2. Добавление только по названию, без ввода ID

Отменяется в корректировке №1:

| Что | Действие |
|---|---|
| Раздел 6.3 «Добавить по ID вручную» | **Удалить целиком**, в интерфейсе нет поля для ввода `item_id` |
| Раздел 6.1: «Поиск по `item_id` напрямую» | **Удалить** |
| Раздел 5.3: различение «ID не найден» и «не торгуется» | Упростить: все предметы в списке выбраны из каталога, значит `400` на пробный запрос = **«не торгуется на аукционе»** |
| Критерий приёмки №3 (добавление по ID вручную) | Заменить критерием из раздела 7 этого файла |

Пользователь **никогда не видит и не вводит ID**. Идентификаторы используются только внутри системы (ключи таблиц, импорт/экспорт списка в JSON).

## 3. Поиск по человеческому названию (уточнение требований)

- Поиск по названиям на всех языках каталога (ru/en/es/fr/ko); язык отображения по умолчанию — русский, переключатель в интерфейсе.
- Нормализация: регистр, `ё → е`, «ёлочки» и кавычки, дефисы, лишние пробелы не влияют на поиск.
- Совпадение по подстроке и по началу слов; лёгкая нечёткая сопоставка (опечатка в 1–2 буквы) на клиенте по `catalog.json`.
- **Ранжирование результатов:** точное совпадение → начало названия → начало слова → подстрока → нечёткое. Совпавший фрагмент подсвечивать.
- **Одинаковые или похожие названия** (разные ранги, варианты, категории) обязательно различать в списке результатов: рядом с названием показывать категорию, ранг цветом и иконку, чтобы пользователь выбрал именно нужный предмет.
- Подсказки при пустой выдаче: «Ничего не найдено. Проверьте написание. Возможно, предмета нет в базе EXBO» (см. раздел 5).
- Фильтры по категории и рангу остаются; быстрые фильтры «Оружие», «Артефакты», «Броня», «Расходники» (по реальным категориям каталога).
- Добавление: кнопка «Отслеживать» у результата; сразу после добавления предмет попадает в таблицу списка со статусом «ожидает первого сбора».

## 4. Модули оружия — выбор по названиям

Все модули на аукционе идут под одним `id` `1pyq`, а пользователь мыслит названиями («Фокусный», «Уходящий», «Снайпер»). Поэтому в интерфейсе отдельная карточка **«Модуль оружия»**:

- Три списка выбора по слотам: **Надстройка**, **Отклонение**, **Концепт**, плюс значение «любой». Названия берутся из `title_ru` публичного индекса модулей (`_index.json`, см. раздел 9 справочника) и группируются по полю `group`. `definitionId` пользователю не показывать.
- Минимальный потенциал: ползунок или поле 0…190 (с пояснением, что 190 — максимум) и/или выбор минимальной редкости по названию: Обычный, Необычный, Особый, Редкий, Исключительный, Легендарный, Уникальный.
- Одну такую «подписку» можно создать на конкретную связку («Фокусный Уходящий «Снайпер»») или на нужный слот/название отдельно.
- **Важное изменение схемы** (в корректировке №1 ключ `unique (region, item_id)` не позволяет несколько записей на `1pyq`): список отслеживания должен допускать **несколько записей для одного `item_id` с разными фильтрами**. Добавь колонку `filters_hash` (хэш нормализованных фильтров) и замени ограничение на `unique (region, item_id, filters_hash)`.
- Для артефактов и улучшаемых предметов фильтры по качеству и уровню также выбираются **по названиям** (имена качеств берутся из реальных данных/базы предметов; ключи `additional` определяются по реальным ответам и записываются в `DECISIONS.md`). Числовые коды пользователю не показывать.

## 5. Предметы, которых нет в каталоге

Каталог EXBO неполон: часть торгуемых предметов в нём отсутствует (в справочнике приведены `y1q9` и `0n9q`). Раз добавления по ID в интерфейсе нет, такие предметы в поиске **не найдутся**. Чтобы это можно было исправить без интерфейса ввода ID:

- Сделай в репозитории файл `catalog_overrides.json`: массив записей `{ "id", "name_ru", "name_en", "category" }`. При `sync-catalog` он **объединяется с каталогом EXBO**, и такие предметы отображаются в поиске как обычные, по названию (с пометкой «добавлено вручную» в карточке результата).
- Заполняют его **только данные, предоставленные пользователем или официальной документацией**; агент **не придумывает** ID и названия.
- Для затравки допустима одна запись из официальной документации EXBO: `y1q9` — «Гадюка» (en: Viper), категория `weapon/submachine_gun`. Остальные пропущенные предметы добавляются по мере обнаружения: если пользователь не нашёл предмет по названию, он называет агенту название и ID один раз, и агент дополняет файл.
- Если запись в оверрайдах конфликтует с каталогом EXBO (тот же `id`), приоритет у каталога EXBO, а конфликт пишется в лог `sync-catalog`.

## 6. Остальное без изменений

Ограничение размера списка, backfill истории, бюджет данных, Auth и RLS, фазы работ, дайджест — как в корректировке №1.

## 7. Критерии приёмки (замена пункта 3 из корректировки №1)

1. В интерфейсе нет поля для ввода `item_id` и нигде в UI не показываются идентификаторы предметов.
2. Предмет находится по русскому и по английскому названию, с учётом `ё/е`, регистра, кавычек и опечатки в 1–2 буквы; одинаковые названия различимы по категории, рангу и иконке.
3. Модули оружия добавляются выбором названий из списков (надстройка/отклонение/концепт) и минимального потенциала; можно создать несколько подписок на `1pyq` с разными фильтрами.
4. Предмет из `catalog_overrides.json` находится в поиске по названию так же, как предметы из каталога, и корректно отслеживается.
5. Предмет, отвечающий `400` на аукционные запросы, получает статус «не торгуется» и не опрашивается.
6. Комиссия 5% с цены продажи и нулевой сбор при выставлении применены во всех расчётах и тестах; в сигналах нет оговорок про «неподтверждённую комиссию».
