# Корректировка №3: интерфейс и функции уровня «терминала аукциона»

> **Приоритет (от высшего к низшему):** этот файл → `stalcraft-auction-bot-patch-2-names-only.md` → `stalcraft-auction-bot-patch-watchlist.md` → `stalcraft-auction-bot-agent-prompt.md`.
> Этот файл **полностью заменяет** описание интерфейса (раздел 10 основного промпта и раздел 6 корректировки №1). Бэкенд, API-правила, комиссия 5%, выбор предметов только по названиям, Auth/RLS, бесплатная инфраструктура — остаются как есть, если ниже не сказано иное.

---

## 0. Зачем этот файл

Пользователь показал референсы: платный трекер аукциона с живой лентой выгодных лотов (карточки с иконкой, цветом редкости, скидкой, прибылью, ROI, «надёжностью», глубиной стакана и кнопкой «Куплено»), каталог предметов карточками со спарклайнами и разделы «Сделки», «Рынок», «Поиск», «Журнал/Оповещения» с отдельной панелью «Точность сигналов по факту».

Текущая версия интерфейса — плотная серая таблица, и по скриншоту видны конкретные дефекты:

1. Сырые технические коды вместо человеческих названий категорий: `other`, `containers`, `artefact/electrophysical`, `artefact/thermal`.
2. Нет иконок предметов, нет цветового кода редкости, нет визуальной иерархии: всё выглядит одинаково.
3. Шапка сломана: кнопки «Для нейросети» и «Обновить» налезают друг на друга и обрезаны; шесть вкладок с непонятными названиями («Каталог и Добавление», «Анализ предмета», «Здоровье системы», «Конфигурация»).
4. Единственный режим — таблица; нет ленты, карточек, графиков, действий «куплено/пропустить».
5. Одинаковые «Мин. ROI / Мин. профит» в каждой строке занимают место, а полезных данных (цена, скидка, прибыль) на экране нет.

**Цель:** интерфейс, который не стыдно показать рядом с референсами, при этом бесплатный, для одного пользователя, без paywall'ов. Референсы — источник идей по UX, а не по брендингу: **не копируй их названия, тексты, логотипы, ассеты и код**, делай собственный дизайн.

## 1. Честные ограничения (показывать в интерфейсе, не скрывать)

- У референсов заявлены «задержка <1 секунды» и «живой поток аукциона». У нас такого **не будет**: официальный API отдаёт данные с отставанием ~10 минут, а бесплатный планировщик запускается не чаще раза в 5 минут. Поэтому:
  - Индикатор в шапке называется не «live», а **«Данные: N мин назад»** (цвет по порогам: зелёный ≤ 12 мин, жёлтый ≤ 25, красный дальше) и всегда виден.
  - На карточке лота два времени: «появился в нашем сборе N мин назад» и «выставлен N мин назад по данным игры» (из `startTime`), плюс «осталось …» (из `endTime`).
  - В тултипе у «Куплено» и в подвале ленты: «Лот мог быть выкуплен за время задержки данных».
- «Мгновенность» внутри открытой страницы достигается **подпиской Supabase Realtime** на вставку новых сигналов: после каждого запуска сборщика лента обновляется сама, без перезагрузки (проверь актуальные лимиты Realtime на бесплатном плане; запасной вариант — опрос каждые 60 секунд). Вне браузера уведомляет Telegram (раздел 8).
- Отметки «куплено» и «пропущено» делает человек: API игры ничего не знает о ваших покупках.

## 2. Информационная архитектура (вместо шести вкладок)

Верхнее меню, слева направо:

| Вкладка | Что это |
|---|---|
| **Лента** | Главный экран: новые выгодные лоты карточками, свежие сверху |
| **Сделки** | Таблица всех сигналов с фильтрами, итогами и отметками |
| **Рынок** | Что дорожает/дешевеет, обороты, где спрос обгоняет предложение |
| **Предметы** | Каталог карточками: поиск по названию, спарклайны, добавление в отслеживание, управление списком |
| **Журнал** | История оповещений и сигналов, панель «Точность сигналов по факту» |
| **Позиции** | Что куплено и что продавать (когда и за сколько) |

Справа в шапке: переключатель региона (RU/EU/…), индикатор свежести данных, кнопка **«Дайджест»** (копировать/скачать JSON для нейросети), значок звука, меню профиля, а в нём — **«Настройки»** (пороги, комиссия, часовой пояс, каналы оповещений) и **«Состояние системы»** (здоровье сборщика, размер БД). Эти два раздела не должны занимать место в основной навигации.

Шапка адаптивна: на узких экранах навигация превращается в нижнюю панель или бургер; кнопки не накладываются и не обрезаются ни на какой ширине от 360 px.

## 3. Лента (главный экран)

Карточки, свежие сверху. Опорная раскладка (колонки на широком экране, стек на мобильном):

**Левая часть карточки**
- Иконка предмета (из базы предметов EXBO; если нет — аккуратный плейсхолдер, не пустая рамка).
- Название крупно; рядом уровень заточки (`+15`) если есть; бейдж «НОВОЕ» первые N минут; кнопка «копировать название».
- Чипы: **категория по-русски** (артефакт, контейнер, расходник…), **редкость** названием («Особый») цветом по палитре (раздел 7), **надёжность** с подписью («70 · Смело»), «26 продаж за 3 дня», «в стакане 43» (глубина предложения: число лотов с ценой не выше целевой цены продажи).
- Строка времени: «1 мин · ещё 5ч 48м».

**Правая часть карточки (числа, моноширинный шрифт с табличными цифрами)**
- **Цена/шт** — цена покупки за штуку.
- **Выставить** — рекомендуемая цена выставления за штуку.
- **Скидка** — насколько покупка ниже честной цены (`buy / fair − 1`, например −25,7%) + полоска/точки силы сигнала.
- **Прибыль** — чистая, после комиссии 5% с цены продажи, за весь лот; рядом **ROI**.
- Кнопки: **«Куплено»**, **«Пропустить»**, значок графика (открывает карточку предмета в боковой панели).

**Раскрытие карточки (клик):** блок «Почему» (`reasons`, человеческим текстом с цифрами), блок «Риски» (`caveats`), мини-график цены сделок за 7 дней с отметкой цены лота и целевой цены продажи, лесенка предложения (стакан) вокруг цены, таблица последних сделок, «когда выставлять» (окно по сезонности, если данных достаточно).

**Панель фильтров над лентой:** регион, редкость (мультивыбор), прибыль от, надёжность от, заточка от–до, категория, «только мои предметы» (по умолчанию все отслеживаемые), сортировка (по свежести / прибыли / ROI / скидке / надёжности). Фильтры сохраняются как **пресеты** (создать, переименовать, удалить), активный пресет запоминается.

**Прочее:**
- Переключатель **звукового сигнала** (Web Audio; включается жестом пользователя; громкость; разные тоны для разной силы сигнала). Опционально системные уведомления браузера.
- Ссылка «таблица →» открывает вкладку «Сделки».
- Раздел **«Ранее»**: свёрнутые компактные строки прошедших сигналов с их исходом («ушёл», «истёк», «куплено», «пропущено»).
- «Куплено» открывает мини-окно: цена и количество подставлены из лота и редактируются; результат создаёт **позицию** (вкладка «Позиции»).
- Анимация появления новых карточек сдержанная; уважать `prefers-reduced-motion`.
- Пустое состояние («Сигналов по текущим фильтрам нет», с подсказкой, какой фильтр отсёк больше всего), состояние загрузки (скелетоны), состояние ошибки с понятным текстом.

## 4. Сделки

Таблица всех найденных сигналов, **со всеми** теми же данными, что в карточке, и итогами.

- Сводка сверху: активных сигналов, лучшая скидка, потенциал чистыми (сумма ожидаемой прибыли по активным), число отмеченных «куплено/пропущено».
- Фильтры: категория, скидка, редкость, состояние сделки (новая / активна / куплена / пропущена / ушла / истекла), период.
- Отметки «куплено» и «пропущено» прямо в строке, массовые отметки, выбор колонок, сортировка по любой колонке, экспорт CSV.
- Колонки не «сырые»: названия категорий и редкостей по-русски, деньги с разделителями разрядов и символом валюты региона (для RU — ₽, символ задаётся конфигом региона).

## 5. Рынок

Данные **только по отслеживаемым предметам** (заголовок должен это явно говорить: «Рынок · ваши N предметов»).

- Движение цен по категориям (изменение медианной цены за окно 24ч / 3д / 7д / 30д), топ растущих и падающих.
- Обороты за выбранное окно: штуки и сумма сделок по предмету и по категории.
- Предметы, где **спрос обгоняет предложение**: продажи в сутки растут, а глубина стакана падает (метрика и порог — в `analytics/`, объяснение в тултипе).
- Окно переключается теми же кнопками диапазона, что и в остальных местах.

## 6. Предметы и страница предмета

**Каталог карточками** (как «Аукцион» в референсе №2): иконка, название, «категория · ранг», спарклайн цены за 7 дней, «Цена за единицу», «Продаж за 24ч». Для предметов, которые не отслеживаются, данных нет, и вместо цены показывается «—»; там же кнопка **«Отслеживать»**. Поиск по названию в шапке раздела — по требованиям корректировки №2 (без ID, с `ё/е`, регистром, опечатками, ранжированием). Для отслеживаемых — быстрые действия: пауза, пороги, удаление.

**Страница предмета** (боковая панель или отдельный экран):
- Медиана сделок и **текущий пол стакана** (минимальная цена за штуку среди активных лотов).
- График истории цен с диапазонами **24ч / 3д / 7д / 30д / 90д** (глубина ограничена хранением, см. бюджет данных), переключение «медиана / среднее».
- Разбивка по **качеству и заточке** (для артефактов), для модулей — по полосам потенциала.
- **Лучший час торга:** когда покупают дешевле, а продают дороже (карта «день недели × час»). Показывать только при достаточном числе сделок в каждой ячейке, иначе ячейка серая с пометкой «мало данных»; часовой пояс выбирается в настройках и подписан на графике.
- Лесенка предложения (стакан) в виде гистограммы по ценовым уровням.
- Таблица последних сделок и список активных лотов.
- Сводка сигналов по предмету и индивидуальные пороги.

## 7. Визуальный дизайн

- **Тема:** тёмная «терминальная» (глубокий тёмный фон, едва заметная сетка/градиент, акцентный янтарно-оранжевый цвет для главных действий). Допустима светлая тема — по желанию, не в ущерб качеству тёмной.
- **Типографика:** выразительный гротеск для заголовков и моноширинный шрифт с **табличными цифрами** (`font-variant-numeric: tabular-nums`) для всех цен и процентов; числа выравнены по правому краю. Шрифты — из бесплатных, с запасными вариантами; только кириллические начертания.
- **Редкость** — цветом рамки/свечения карточки и чипа. Стартовая палитра (уточни по реальным данным и скриншотам игры): Обычный — серый, Необычный — зелёный, Особый — синий, Редкий — пурпурно-розовый, Исключительный — красный, Легендарный — оранжево-золотой, Уникальный — особый акцент (например, бирюзовый/радужный контур). Соответствие числовых кодов качества (`qlt` / `quality`, 0…6) названиям определи по реальным данным и зафиксируй в `DECISIONS.md`. **Цвет — не единственный носитель смысла:** всегда подпись названием редкости.
- **Прибыль** — зелёным, убыток/отрицательные значения — красным; скидка с подсветкой силы; надёжность — подпись по шкале (пороги настраиваются): ниже 40 «Рискованно», 40–69 «Осторожно», от 70 «Смело». Подписи привязаны к **откалиброванной** уверенности (раздел 9 про калибровку), а не к «красивым» числам.
- **Категории и названия — только по-русски.** Заведи в репозитории словарь `category_ru.json` (slug → русское название; например `artefact` → «Артефакт», `artefact/electrophysical` → «Артефакт · электрофизический», `containers` → «Контейнеры», `other` → «Прочее»). Неизвестный slug отображай в человекочитаемом виде (первая буква заглавная, `/` → « · »), **никогда не показывай сырой slug** в основном интерфейсе. Недостающие переводы агент берёт из данных базы предметов (например, из описаний предметов) и заводит в словарь.
- **Иконки:** везде, где есть предмет; ленивая загрузка; плейсхолдер при отсутствии. Для кэша используй `loading="lazy"` и фиксированные размеры, чтобы не прыгала вёрстка.
- Числа форматировать единообразно: `149 960`, `+23 574`, `−25,7%`, длинные суммы допустимо сокращать в компактных строках (`231k`), в основной карточке показывать полностью.
- Адаптивность: проверено от 360 до 2560 px; никаких горизонтальных прокруток страницы; таблицы прокручиваются внутри своего контейнера.
- Доступность: контраст текста не ниже WCAG AA, фокус-кольца, управление с клавиатуры (хотя бы навигация, фильтры, «Куплено/Пропустить»), `aria-label` у иконочных кнопок.
- Производительность: виртуализация длинных списков, дебаунс поиска, ленивая загрузка графиков, лёгкая библиотека графиков; бюджет JS-бандла главной страницы — до ~300 КБ gzip (измерь и приложи отчёт).

## 8. Журнал и оповещения

**Журнал:** хронология сигналов и оповещений: что за предмет, когда появился сигнал, ушёл ли лот, чем закончилось (куплено / пропущено / истёк / ушёл другим), в какой канал отправлено.

**Каналы доставки (бесплатные):**
- **Telegram** (личный бот): сообщение с названием, ценой за штуку, ценой выставления, чистой прибылью, ROI, надёжностью, коротким «почему» и временем «осталось».
- **Discord** через входящий вебхук (по желанию): то же содержимое.
- Секреты каналов — только в Secrets/БД под RLS, не в публичных файлах репозитория.

**Настройки оповещений:** пороги чистой прибыли и надёжности отдельно для каналов, **тихие часы** (часовой пояс и интервалы, когда ничего не отправляется; сигналы всё равно копятся в ленте), дедупликация (один лот — одно оповещение; повтор при существенном изменении цены), лимит оповещений в час, пауза каналов одной кнопкой.

### Панель «Точность сигналов по факту»

Реализовать честно и с публичной методологией в самом интерфейсе. Определения (зафиксируй в коде и в тексте панели):

- **Горизонт** — срок, через который проверяется сигнал (по умолчанию 24 ч; на выбор 6 ч / 24 ч / 3 д).
- **Попадание по направлению:** к горизонту медианная цена сделок по сегменту предмета **не ниже** цены на момент сигнала (точность направления).
- **Реализуемость прибыли:** в течение горизонта состоялась хотя бы одна реальная сделка по сегменту по цене не ниже `buy_unit / 0.95 × (1 + min_margin)`, то есть сделка по рекомендованной цене выставления была бы чистой прибылью после комиссии.
- Показывать оба показателя, **число сигналов в выборке (n)** и доверительный интервал (например, Вильсона). При n меньше порога — «мало данных».
- **Окна:** первым номером — свежий срез за 7 дней («текущая форма»), ниже — «за всё время» (глубина зависит от накопленных сигналов). Разбивка по категориям и по уровню надёжности.
- **Калибровка:** график «заявленная надёжность → фактическая доля попаданий». Подписи «Смело/Осторожно/Рискованно» корректируются по этой калибровке.
- Под панелью обязательная приписка в духе: «Это точность направления и реализуемости по историческим сделкам, а не гарантия прибыли и не точность самой цены».
- Здесь нет «самообучающейся модели» по умолчанию: калибровка порогов и весов — простой, воспроизводимый расчёт по накопленным исходам. Усложнять модель можно, только если бэктест показывает пользу.

## 9. Позиции (куплено → продавать)

- «Куплено» в ленте создаёт позицию: предмет, количество, цена покупки за штуку, время.
- Для каждой позиции — **сигнал продажи**: рекомендуемая цена выставления (с учётом 5%), нижний порог, когда выставлять, ожидаемое время продажи, предупреждения (рынок падает, предложение растёт), а также «безубыточная цена продажи» (`buy / 0.95`).
- Закрытие позиции: «Продано» с фактической ценой → факт прибыли попадает в итоги (за день/неделю/всё время) и в журнал.

## 10. Изменения данных и бэкенда под эти функции

Добавь (миграции, с RLS «только владелец», как в корректировке №1):

- `signal_status` — отметки пользователя по сигналам: `new | bought | skipped`, время, цена и количество при покупке.
- `positions` — позиции: предмет/сегмент, количество, цена покупки, время, статус `open | sold`, цена продажи, время продажи.
- `notifications_log` — отправленные оповещения: канал, время, сигнал, статус доставки; `notification_settings` — пороги, тихие часы, лимиты, часовой пояс.
- `signal_outcomes` — исходы сигналов по горизонтам (для панели точности).
- `item_state` — **одна строка на отслеживаемый предмет**, перезаписывается каждым циклом: текущий пол стакана, лесенка предложения (агрегированные ценовые уровни), глубина стакана, медианы по окнам, «продано за 24ч/3д», спарклайн-точки за 7 дней. Это даёт быстрые карточки «Предметов» и «Рынка» без тяжёлых запросов.
- `hour_stats` — сводка «цены и объём по дню недели и часу» по предмету (для «лучшего часа»).
- Словарь `category_ru.json` и палитра редкостей — в репозитории (не секреты).
- Метки предметов: название, иконка, категория, ранг — из каталога (корректировки №1–2).
- Realtime: публикация вставок в `signals` для подписки интерфейса (учти RLS: подписка работает только у владельца).
- Бюджет данных: все новые таблицы учесть в расчёте размера БД (раздел 7 корректировки №1). `item_state` и `hour_stats` компактны.

## 11. Порядок работы (чтобы не повторилась ситуация с «серой таблицей»)

1. **Сначала дизайн-макет на тестовых данных, без подключения к бэкенду.** Статическая сборка с seed-данными (минимум: 25 предметов разных категорий и редкостей, 40 сигналов, графики, позиции, журнал, панель точности). Режим демо включается переключателем и нужен также для проверки интерфейса без живого API.
2. Автоматические скриншоты (Playwright или аналог) всех экранов на ширинах **360, 768, 1024, 1440, 1920** в тёмной теме (и в светлой, если есть). Агент сам просматривает их и исправляет дефекты до показа пользователю.
3. Показать пользователю скриншоты макета и **дождаться одобрения** направления дизайна. Только после этого подключать реальные данные.
4. Подключение к Supabase, Realtime, звук, оповещения, пресеты.
5. Финальная проверка по чек-листу ниже, с приложенными скриншотами и отчётом о бандле.

## 12. Чек-лист качества интерфейса (обязателен перед сдачей)

- [ ] Нигде в UI нет сырых slug'ов категорий и технических кодов (`other`, `artefact/electrophysical`, `qlt`, `definitionId`).
- [ ] У каждого предмета есть иконка или аккуратный плейсхолдер.
- [ ] Редкость показана цветом **и** названием; палитра единая во всех разделах.
- [ ] Шапка не ломается ни на одной ширине от 360 px; кнопки не накладываются и не обрезаются.
- [ ] Все числа выровнены, с разделителями разрядов и табличными цифрами; деньги с символом валюты региона.
- [ ] В ленте для каждого лота видны: цена/шт, цена выставления, скидка, чистая прибыль и ROI, надёжность с подписью, продажи за 3 дня, глубина стакана, время появления и «осталось».
- [ ] Индикатор «Данные: N мин назад» виден всегда и корректно окрашивается.
- [ ] Есть состояния: загрузка, пусто, ошибка, нет данных (мало сделок).
- [ ] Звуковой сигнал, пресеты фильтров, отметки «куплено/пропустить», позиции работают.
- [ ] Панель «Точность сигналов по факту» показывает n, доверительный интервал, оба показателя, калибровку и приписку о том, что это не гарантия.
- [ ] Telegram (и по желанию Discord) оповещения работают, тихие часы и дедупликация проверены тестом.
- [ ] Консоль браузера без ошибок; Lighthouse (производительность и доступность) не хуже 85 на главной, результат приложен.
- [ ] Приложены скриншоты на всех проверенных ширинах.

## 13. Критерии приёмки (дополнение)

1. Интерфейс соответствует разделам 2–9; все пункты чек-листа раздела 12 выполнены и подтверждены скриншотами.
2. Отслеживаемый предмет с лотом, дающим сигнал, появляется в ленте после очередного цикла сборщика без перезагрузки страницы (Realtime или опрос не реже раза в 60 секунд).
3. «Куплено» создаёт позицию и сигнал продажи; «Продано» фиксирует прибыль и обновляет итоги.
4. Оповещение в Telegram приходит один раз на один лот, соблюдает тихие часы и пороги.
5. Панель точности считает исходы по заданным определениям; на синтетическом наборе из тестов результат совпадает с ручным расчётом.
6. Бэкенд, бюджет данных и ограничения API не нарушены: сборщик по-прежнему опрашивает только список отслеживания, и новая функциональность не увеличивает число запросов к API.
